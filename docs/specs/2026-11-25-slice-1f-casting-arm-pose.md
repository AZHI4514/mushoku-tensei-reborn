# 切片 1f · 施法的手臂动作

2026-11-25 · 待 AZHI 评审

## 动作设计

按住 R 且服务端接受咏唱后，施法者向前抬起右臂，使右肩至右腕的连线与地平线平行。左手从身体左侧靠拢，掌端搭住右腕，即右手掌略靠前臂的一段。左右按施法者自身判定，游戏设为左主手时也采用这一姿态。第一人称和旁观者看到相同的施法侧。

| 时刻 | 玩家与旁观者应看到的动作 |
|---|---|
| 起手 | 用 5 tick 从当前姿态抬起右臂。第 5 tick 结束时右臂向前平举，左手已搭上右腕。 |
| 持续咏唱 | 双臂保持搭腕。玩家走动时腿部正常迈步。两手各自持有的物品全程可见，位置与朝向跟随握住它的手。 |
| 完成 | 水弹生成时双手仍在搭腕。随后用 5 tick 放回正常姿态。持续按住 R 不会重播起手。 |
| 中断或拒绝 | 松键中断时，从当时的姿态开始放手，5 tick 后回到正常姿态。请求被拒绝时保持原姿态。 |

抬手和放手各 5 tick 是首轮试玩值。抬手计入既有的 100 tick 咏唱，放手只在客户端播放。

## 与咏唱和锚点的关系

**每个新生成的咏唱水花和咏唱完成时发射的水弹，都必须从施法者当时的右掌中心出现。** 右掌中心取右臂模型末端面的中心。起手的 5 tick 内，水花生成点随右掌抬升；稳定搭腕后，生成点位于平举的右掌。左右主手、静止或步行、平视或大幅俯仰、空手或持物均适用。已经生成的水花按自身生命周期运动。

1f 将 1e 按主手镜像、随视线俯仰计算的起点改为施法姿态的右掌锚点。客户端手臂渲染、咏唱水花和服务端水弹发射共用同一套右掌位置计算；给定同一玩家姿态和咏唱进度，两端应得到同一世界坐标。准星决定瞄准方向，右掌决定出生位置。准星对准、近距过渡和眼到手的防穿墙判定沿用 1e 验收标准。[1e 锚点规格](2026-11-21-slice-1e-anchor.md)

客户端复用服务端同步的咏唱状态。周期性同步维持当前动作，中途进入可见范围的旁观者直接看到当前阶段。完成或松键中断时播放收势，死亡、离线或切换世界时清理对应玩家的姿态。玩家渲染仅在客户端加载。[魔术模块 §3、§5.1、§7、§10](../modules/magic.md)

## 游戏内验收

双客户端同服。A 施法，B 在同步范围内旁观。分别把 A 设为右主手和左主手，各执行下表。用 tick 步进检查起手和收势，以各客户端收到相应状态为计时起点。

| WHEN | SHALL |
|---|---|
| A 空手平视并按住 R，B 从正面和侧面观察 | A 第一人称能看到右臂抬起、左手搭腕和准星。起手第 5 tick 结束时，B 从侧面看到右肩与右腕等高，从正面看到左掌端贴住右腕。 |
| A 从起手到搭腕分别静止和正常步行，平视、抬头和低头，B 中途进入观察范围 | A 和 B 看到每个新水花都从当时的右掌出现，起手期间随手抬升。以同一逻辑 tick 和姿态采样，两端每次生成水花的位置距各自右掌锚点均 ≤0.001 格。B 用第三人称右臂末端面中心核对锚点，A 在第一人称核对右掌与水花的可见起点。 |
| A 双手各持一件外形易区分的物品，完成起手、搭腕和放手 | A 和 B 均能辨认两件物品，每件都随原先握住它的手移动和转动，全程可见。 |
| A 以 37 点魔力对无遮挡目标完成一次咏唱并继续按住 R，分别在平视、抬头和低头时重复 | 第 100 tick 水弹从仍在搭腕的右掌中心出现，每轮魔力从 37 变为 36。A 和 B 均能看到水弹从右掌飞出，服务端出生坐标距完成 tick 的右掌锚点 ≤0.001 格。完成后第 5 tick 结束时双手已放下。 |
| A 在抬手途中或稳定搭腕后松开 R，另以 0 魔力尝试起手 | 中断时双手从当前姿态放下，5 tick 后回到正常姿态，无弹体且魔力保持原值。零魔力时两端均保持原姿态。 |
| A 在咏唱中死亡、离线或切换维度，再与 B 相遇 | A 和 B 均看到正常手臂姿态，下次按 R 能从待机重新起手。 |

## 需要 AZHI 裁决的问题

无。AZHI 已确认水花和水弹始终从右掌出现。
