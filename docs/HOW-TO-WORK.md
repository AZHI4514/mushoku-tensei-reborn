# 人类操作手册 — 怎么指挥 AI 做完这个 mod

> 给 AZHI 一个人看。AI 不需要读这本。
> 目的：你任何时候不知道该干什么，翻这一份就够。

---

## 0. 你的角色：只做三件事

| 你做的事 | 频率 | 花多久 |
|---|---|---|
| **填表**（数值、配色、内容清单） | 每片开始时 | 10–30 分钟 |
| **审文档**（spec / plan / 模块文档） | 每片两次 | 各 5 分钟 |
| **进游戏试玩** | 每片结束时 | 5–10 分钟 |

**你不做的事**：不写代码、不建目录、不查 API、不改 gradle、不 debug。
那些是 AI 的活。你插手技术细节，只会让文档和代码不一致。

## 1. 文件权限表（谁改什么，你何时打开）

| 文件 / 目录 | 谁写 | 你什么时候打开 | 禁止 |
|---|---|---|---|
| `AGENTS.md` | AI 写，你审 | 每片结束时看一眼「已实现边界」 | 别自己加内容，它只指路 |
| `docs/VISION.md` | **你** | 只在想改方向时 | 别让 AI 改，这是你的宪法 |
| `docs/PRINCIPLES.md` | **你** | 当两个想法冲突时 | 别让 AI 改 |
| `docs/ROADMAP.md` | 你 + AI 建议 | 决定先做哪个模块时 | — |
| `docs/modules/magic.md` | AI 起草，**你填空表** | 每片开始前 + 结束后 | 别让 AI 填数值 |
| `docs/specs/` | AI 写，你审 | 每片开始时（最重要） | 交付后不许再改，改了就不是历史了 |
| `docs/plans/` | AI 写，你审 | 每片开始时 | 同上 |
| `src/` 全部 | **AI 全权** | 不用看 | 你别手改代码，改了就没人知道现状 |
| `docs/setting-bible/` | 只读 | 想查「原作怎么写的」时 | 别让 AI 把它当需求 |
| `tests/contracts.py` | AI 维护 | 看红绿结果 | — |

**一句话记法**：宪法你写，模块你填数，切片你审，代码你别碰。

## 2. 你的四句话（直接复制粘贴给 AI）

### 第一句 —— 让它写 spec
```
读 AGENTS.md 和 docs/modules/magic.md。
写 <切片名> 的 spec，放到 docs/specs/<日期>-<切片名>.md。
不要写代码。末尾列出需要我裁决的问题。
```

**它应该回**：一份 spec，含四块 —— 目标 / 玩家可见循环 / 验收标准
（WHEN…SHALL 句式）/ 硬约束，末尾附 3–6 个待你裁决的问题。

**你审什么**（5 分钟，看四件事）：
1. 目标是一句话能说清的吗？说不清 = 这切片太大，让它拆。
2. 验收标准是不是每条都能「进游戏试出来」？不能试的删掉。
3. 有没有偷偷加你没要求的内容？有就删。
4. 它问你的问题，你能答吗？答不了就让它先给 2–3 个方案。

### 第二句 —— 让它写 plan
```
按这份 spec 写实施计划，放到 docs/plans/<同名>.md。
每项任务要能在 10–30 分钟内做完，标出依赖关系。
```

**它应该回**：checkbox 任务清单 + Global Constraints 段（版本号、不可违反项）。

**你审什么**（3 分钟，看三件事）：
1. 有没有大任务没拆开（如「实现施法系统」）→ 让它拆。
2. 顺序对不对（先注册再引用）。
3. 有没有任务需要你提供资源（贴图/音效）→ 这些要先列出来给你。

### 第三句 —— 让它干活
```
执行 plan。每完成一项勾掉。全部完成后跑 python tests/contracts.py，
红了先修完再报告。
```

**它应该回**：逐项汇报 + 契约结果。契约必须绿。

**你审什么**（2 分钟）：
1. 契约是不是绿的（红的就是没干完）。
2. 有没有「顺手把 X 也做了」（超范围）。

### 第四句 —— 收尾
```
更新 AGENTS.md 的已实现边界。
把 spec 里定下来的决策回写到 docs/modules/magic.md。
列出这次发现的新问题。
```

**它应该回**：三份文档的更新 + 问题清单。**这一步不做，下一片它就会自相矛盾。**

## 3. 什么时候描述需求、怎么描述

**原则：先改表，再写代码。永远不要在对话里口头加功能。**

因为口头加的东西不会进文档，下一片 AI 就忘了（或者更糟：它记得一部分，
做出半套）。

### 场景 A：想加一个法术
不要说「加个冰冻法术」。**去 `magic.md` 第 5 节加一行**，填你能填的格子：

```
| `water_ice_spear` | 中 | 消耗? | 咏唱? | 冰枪命中后定身 2 秒 | 我新加的 |
```
然后说：「magic.md 第 5.1 节我加了一行，把空格子给我三个候选取值。」

### 场景 B：觉得哪个法术手感不对
不要说「火球太弱」。说三件事：**现状 / 想要什么 / 用哪几个词形容**

```
火球现在打不动怪。我要它是初级里最强的攻击术，
但耗魔要明显比水弹贵。手感上要「重、慢、一下打残」。
```
它会给你 2–3 组具体数值方案让你选。**如果它直接改了没给方案，退回去重来。**

### 场景 C：想加一个新系统（比如打坐回魔）
不要描述机制，**描述玩家的动作和处境**：

```
玩家不打怪的时候魔回得很慢，需要主动坐下来。
坐下有风险（会被打断），在安全的地方恢复更快。
```
它负责翻成状态机 + 验收句。

### 场景 D：视觉需求
见第 5 节，视觉分两条路，写法完全不同。

## 4. 视觉：两条路，别混

### 路 A：你自己画的像素资源（AI 只接线，不生产）

开工前先让它出清单：
```
列出这个切片需要的全部贴图：文件名、尺寸、放哪个目录、干什么用。
不要生成任何图片文件。
```
你照着清单画（建议 16×16，和 vanilla 一致），丢进它说的目录。
它负责写代码引用 + 契约脚本查「有没有漏」。

**红线**：在 AGENTS.md 里已经写了「资源缺失时报错，不许生成占位图」。
如果它还是给你塞了一堆丑 PNG，删掉并要求它改成报错。

### 路 B：MC 原生效果（粒子 / 方块 / 音效 / 屏幕）

这些**必须写进 spec 的验收句**，否则它会随便挑个粒子敷衍你。

写法示例（你自己写或让它写，然后你审）：
```
WHEN 咏唱开始 THE SYSTEM SHALL 在魔杖尖端持续生成火属性粒子，
咏唱中断时粒子立即消失。
WHEN 火球命中方块 THE SYSTEM SHALL 播放命中音效，
并在受击面留下 3 秒火焰。
```

**判断分界**：
- 影响「玩家看不看得出发生了什么」→ **spec 阶段**（验收标准）
- 只是「好不好看」→ **plan 阶段**（实现细节）
- 全局视觉语言（四属性配色）→ **模块文档第 10 节**（开工前一次定死）

**现实提醒**：MC 的天气是全局的，做「局部下雨」成本很高。
雷系建议用粒子 + 音效模拟，别碰 weather API。

## 5. 从零到第一次进游戏（照做）

### Step 1 · 装环境（30 分钟，一次性）
- 装 **JDK 21**（Temurin，官网选 21，一路下一步）
- 装 **IntelliJ IDEA Community**（免费版够用）
- 确认 `java -version` 显示 21

### Step 2 · 让 AI 做切片 0（骨架）
```
读 AGENTS.md。写切片0（项目骨架）的 spec 和 plan，然后实施。
骨架包括：Gradle + ModDevGradle 工程、@Mod 入口类、
空的 registry 包、能跑的 python tests/contracts.py。
完成后 ./gradlew build 必须成功，contracts 必须绿。
```
你会看到它建 `gradle.properties`、`build.gradle`、`Mushoku.java`、
`registry/` 等。**你不用看懂，只要看结果。**

### Step 3 · 验收切片 0（你亲手跑）
```
cd <项目目录>
./gradlew build
python tests/contracts.py
```
- 第 1 条出 `BUILD SUCCESSFUL` = 通过
- 第 2 条出「全部通过」= 通过
两条都绿，骨架成了。

### Step 4 · 写切片 1 的 spec
```
写切片1的 spec：魔力值 + 一个法术（水弹）+ 完整咏唱施放闭环。
不要写代码。
```
审完 spec，再让它写 plan，审完 plan。

### Step 5 · 填数值（**这是你的活**）
打开 `docs/modules/magic.md`：
- 第 4 节：等级×属性矩阵，把「水」的「初」格填 `✔`
- 第 5 节：只留 `water_waterball` 一行，填消耗、咏唱、效果
- 第 10 节：水的配色（比如 主色 #4FC3F7 副色 #E1F5FE）

填完说：「magic.md 我填完了，按这份数值执行 plan。」

**记住**：填表比说话有效。填完的表 = 需求，说过的话 = 空气。

### Step 6 · 执行
```
执行 plan，完成后跑 contracts。
```

### Step 7 · 第一次进游戏（你亲手）
```
./gradlew runClient
```
进游戏后：
1. 新建创造模式世界
2. 打开背包搜索 `apprentice_wand`（初学者魔杖）
3. 拿到手里 → 右键按住 → 看是不是开始咏唱（粒子 + 音效）
4. 松开 → 应该中断，魔力不掉
5. 灌满 → 应该放出水球
6. 打到方块上 → 应该有命中粒子

**看到什么不对，不要描述解决方案，描述现象**：
> 「按住右键没反应」
> 「水球飞出去了但没有粒子」
> 「松开后魔力还是掉了」

它会去查。你说「粒子太少」它就会去猜。

出 bug 时它需要日志：`runs/client/logs/latest.log`，
直接说「看 latest.log 里的报错」，它自己去读。

## 6. 红旗信号：AI 开始跑偏的迹象

看到这些立刻叫停：

| 现象 | 说明 | 你怎么说 |
|---|---|---|
| 它开始生成 `.png` 占位图 | 违反约定 | 「删掉，改成资源缺失报错」 |
| 它说「顺手把 X 也做了」 | 超范围 | 「回退，只做 plan 里的」 |
| 它交付时没跑 contracts | 没验收 | 「先跑 contracts 再报告」 |
| 它把 ROADMAP 里的东西说成已实现 | 幻觉 | 「检查已实现边界，没实现的不许引用」 |
| 它问你「你想要什么效果」 | 空提问 | 「给我 2–3 个具体方案让我选」 |
| 它自己填了数值 | 越权 | 「数值一律我来定，你给候选」 |
| 它改了 spec 已交付的内容 | 破坏历史 | 「spec 留档不改，改模块文档」 |
| 它一次改了十几个文件 | 切片太大 | 「拆成两片」 |

---

## 7. 心法（只记这一句）

> **你定「要什么」，AI 定「怎么做」；
> 你写在表里，AI 读表干活；
> 每片结束回写文档，否则它下一片就失忆。**
