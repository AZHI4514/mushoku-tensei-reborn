# 切片 1e · 施法锚点精修实施计划

2026-11-21 · 待评审。验收依据为[切片规格](../specs/2026-11-21-slice-1e-anchor.md)。

## Global Constraints

Java 21、Minecraft 1.21.1、NeoForge 21.1.267、ModDevGradle 2.0.148、Gradle Wrapper 9.2.1、GeckoLib 4.7.7。纯数值运算放在 magic/core，玩家与世界读取放在 magic/runtime，手骨与粒子观测限客户端。服务端负责准星选点、发射和命中。保留 100 tick 咏唱、完成扣 1、速度 1.2 格/tick、从手部累计 24 格射程、伤害 6、硬寿命 40 tick。本片沿用现有模型、动画和音效行为。

| 任务 | 耗时 | 依赖 | 实施与完成条件 |
|---|---|---|---|
| 1. 建立手部锚点并验证纯计算 | 25–30 分钟 | 无 | 实现唯一共享入口 `CastAnchor.hand(Player)`，从同一 tick 取眼位、视线、yaw、主手，调用 core 的基底与偏移计算。用 JUnit 验证两侧镜像、平视和俯仰 ±30°、接近及达到 ±90°、基底正交与同输入复算一致；锚点默认不加摆臂。运行 Wrapper test 和契约检查。 |
| 2. 接入咏唱水花 | 10–20 分钟 | 1 | A 和旁观者 B 的客户端均以施法者为参数调用共享入口。移除水花原有的进度前伸量与独立偏移。采集新粒子 addParticle 的原始入参，和同 tick 的 H 对账；两手各测，最大误差 ≤0.001 格。 |
| 3. 接入服务端瞄准与发射 | 25–30 分钟 | 1 | 完成 tick 取 H 和眼射线最近的实体或方块交点 T；处理空瞄、眼到手遮挡与手部行程不足。core 计算单位方向，L2 覆盖 2.9/3.0/3.1 格及 5 格，计算两次归一化初速间的夹角。若硬切超出 5°，调阈值或加过渡插值，验证过渡两端连续、5 格已对准。 |
| 4. 复现并定位移动中断 | 20–30 分钟 | 2、3 | 双客户端同服，A 按住 R 后正常按 W。以 tick 对齐原始键、映射键、界面、C2S 起止包、ACTIVE、A/B 水花及魔力。若中断，按首个分歧定位并修复，再重放同一输入；若未复现，保留操作条件和观测记录。对照组在步行中主动松 R。 |
| 5. 双客户端测手部与粒子 | 20–30 分钟 | 4 | 左右主手分别平视、抬头和低头，站立与匀速步行分别测量。以 B 的第三人称手掌中心作世界坐标参照，保存 A 第一人称画面。分组报告静止/低幅度最大误差 ≤0.15 格、完整步行摆臂周期最大误差 ≤0.30 格；同时核对两端粒子、无遮挡出生点及同姿态复算误差 ≤0.001 格。若考虑摆臂项，按 spec 记录比较并决定是否采用。 |
| 6. 双客户端测靶与阈值 | 20–30 分钟 | 5 | 每只手分别测 5/12/24 格可达靶的 P、T 与误差（各 ≤0.05 格），补斜视和实体靶。固定视线和姿态，移动同一靶面，对 3.0、3.1 格读取服务端实际初速，按 acos(clamp(单位向量点积, −1, 1)) 换算成度。将左右手的实测角度写回 spec；若超限，修正后复测过渡边界与三个靶距。检查贴墙、空瞄及射程外目标。 |
| 7. 验收移动闭环与既有行为 | 20–30 分钟 | 6 | 两手各完成步行 100 tick 与松键对照：记录 ACTIVE、包数、发射数及魔力 37→36/37。运行 Wrapper build、test、runGameTestServer 与 python tests/contracts.py；记录专用服 Done、双端水弹渲染及 1c 分段碰撞和寿命回归结果。将最差样本、日志及失败项记入交付记录。 |
