# 切片 1c · 水弹弹体实施计划

2026-11-21 · 待审。交付口径见[切片规格](../specs/2026-11-21-slice-1c-waterball.md)。

## Global Constraints

- Java 21（Temurin）、Minecraft 1.21.1、NeoForge 21.1.267、ModDevGradle 2.0.148、Gradle Wrapper 9.2.1。
- 实体类型为 `mushoku_tensei_reborn:water_ball`，法术定义 ID 为 `water_waterball`，伤害类型为 `mushoku_tensei_reborn:water`。按模块第 5.1 节取基础伤害 6、速度 1.2 格/tick、最大行程 24 格。
- 沿用 1b 的完成结算。服务端从施法者右手前方发射，方向取完成瞬间的准星，直线匀速、无重力。20 tick 飞行预算加 20 tick 冗余，硬寿命为 40 tick。
- 服务端逐 tick 沿实际行程扫线，裁决最近命中与伤害；客户端仅渲染临时轨迹和原版水花。保留原版盾牌格挡，命中即消失。3D 模型留到 1d。

## 任务与依赖

| 任务 | 耗时 | 前置 | 实施与完成条件 |
|---|---|---|---|
| 1. 建立行程与寿命计算 | 20 分钟 | 无 | 在纯 Java core 中计算剩余行程、末段步长和到期条件。L2 验证 24 格端点、正常 20 步，以及零位移的第 39/40 tick 边界。 |
| 2. 登记实体与伤害类型 | 25 分钟 | 1 | 将 water_ball 的 DeferredRegister 挂入模组总线，创建 Projectile 子类。以数据 JSON 登记 water，验证实体工厂及伤害类型均可按 ID 解析。 |
| 3. 接入发射与飞行 | 25 分钟 | 2 | 在服务端咏唱成功结算分支生成一枚水弹，设置所有者和发射姿态。保存并还原所有者、位移、行程及存活 tick；检查重载后剩余预算。 |
| 4. 实现最近碰撞检测 | 30 分钟 | 3 | 每步先裁剪到剩余射程，再对整段检测方块和候选实体，排除施法者，同距优先方块。覆盖单步越过薄碰撞面的情况；处理末段碰撞后才判定射程耗尽。 |
| 5. 接入伤害与移除 | 20 分钟 | 4 | 在服务端实体命中入口使用 water holder、水弹与施法者构造 DamageSource，调用一次 hurt。沿用原版格挡；命中方块、实体或被格挡均移除。检查普通攻击不能击毁或反弹飞行中的水弹。 |
| 6. 接入客户端临时表现 | 20 分钟 | 3、5 | 用客户端专属入口注册临时飞行表现，使用原版水花显示服务端实际命中点。核对专用服可启动，旁观者能看到同步轨迹。 |
| 7. 验证飞行与生命周期 | 25 分钟 | 4、5 | 在独立 GameTest 源集验证薄板挡弹、射程端点内外、前后目标不穿透，以及静止水弹第 40 tick 移除。用目标生命值、弹体位置和存在性断言。 |
| 8. 联机验收发射与命中 | 30 分钟 | 6、7 | 两客户端核对完成前转向、右手前方发射、准星方向与无下坠轨迹。比对完成与中断的魔力和生成数；实测伤害 6、施法者免伤、挥击无效、正面举盾格挡后弹体消失。记录旁观命中效果。 |
| 9. 交付检查与记录 | 15 分钟 | 8 | 使用 Wrapper 执行 test、build、独立 runGameTestServer，运行 python tests/contracts.py。按规格登记实测结果，通过后更新 AGENTS.md 的已实现边界。 |
