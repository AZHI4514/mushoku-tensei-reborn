# 切片 1a · 魔力可见实施计划

2026-11-21 · 待审。交付条件见[切片规格](../specs/2026-11-21-slice-1a-mana.md)。

## Global Constraints

- 使用 Temurin Java 21、Minecraft 1.21.1、NeoForge 21.1.267、ModDevGradle 2.0.148 和 Gradle Wrapper 9.2.1。
- 魔力上限固定为 100，首次加入和死亡重生均为满值。修改附件默认值时复核死亡回满。
- core 仅用基本类型计算，runtime 负责游戏适配。服务器持有权威值，通过内建附件同步给玩家本人。客户端只读。
- 范围限于魔力存储、调试命令、HUD 与本片测试。施法、按键、自定义网络包、法术、物品、粒子和 GeckoLib 在本片范围外。

## 任务与依赖

| 任务 | 预计用时 | 前置 | 实施与完成条件 |
|---|---|---|---|
| 1. 实现魔力计算 | 15 分钟 | 无 | 在 magic/core 实现固定上限、钳制、扣减和回复。计算过程中避免 int 加法溢出，返回值落在 [0, 100]。 |
| 2. 验证每个公开函数 | 20 分钟 | 1 | 在 src/test/java/com/azhi/mushoku/magic/core/ 逐项实现规格中的 JUnit 5 断言。运行 `./gradlew test`，检查 core 测试报告及公开函数与断言的对应关系。 |
| 3. 注册并持久化附件 | 20 分钟 | 1 | 登记 mana 的 AttachmentType，配置满值默认值、整数持久化和仅发给持有者的同步。读取已有存档，所有新的权威写入经过 core 钳制。 |
| 4. 接入玩家生命周期 | 20 分钟 | 3 | 登录时确保已有存档值或首次默认值同步。死亡后让新玩家实体使用满值并同步。核对切换玩家实体时 HUD 读取当前实体。 |
| 5. 接入调试命令 | 20 分钟 | 3 | 注册权限等级 2 的 get 和 set，接受单个在线玩家。set 接受有符号 int，返回实际写入值并触发同步。 |
| 6. 渲染快捷栏上方的 HUD | 25 分钟 | 4 | 客户端先检查本地玩家及附件是否存在，避免用会创建默认值的读取操作探测同步。同步前留白，收到附件后显示条长和当前值 / 100。 |
| 7. 核对七项游戏内验收 | 30 分钟 | 4、5、6 | 逐条执行规格第 1–7 项。用两名玩家核对隔离。将 A 设为 37 后重登，通过录屏逐帧检查首次显示值；若同步早于首帧，用调试器延后客户端应用首次附件同步再观察，确认等待期间没有满条。 |
| 8. 完成交付检查 | 15 分钟 | 2、7 | 运行 `./gradlew test`、`./gradlew build`、独立的 `./gradlew runGameTestServer` 和 `python tests/contracts.py`。记录 core 用例、游戏内验收结果和命令退出码，通过后更新已实现边界，并将 docs/modules/magic.md 第 8 节的 DataAttachmentType 更正为 AttachmentType。 |
