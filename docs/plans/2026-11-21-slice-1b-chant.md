# 切片 1b · 徒手咏唱实施计划

2026-11-21 · 已执行。按[切片规格](../specs/2026-11-21-slice-1b-chant.md)验收。

## Global Constraints

- Java 21（Temurin）、Minecraft 1.21.1、NeoForge 21.1.267、ModDevGradle 2.0.148、Gradle Wrapper 9.2.1。
- 水弹咏唱持续 100 个服务端游戏 tick。完成时经 Mana.spend 扣 1 点，中断零消耗。
- 状态机与结算判断属于纯 Java core。玩家身份、游戏 tick 与魔力附件由服务端适配层管理。客户端仅提交请求并显示服务端状态。
- 使用原版 minecraft:splash。终态立即停止生成新粒子，已有粒子约 1 秒后自然消亡。弹体、伤害、命中、自定义粒子及 3D 动画留在本片范围外。

## 任务与依赖

| 任务 | 预计用时 | 前置 | 实施与完成条件 |

| 2. 验证 tick 与扣费边界 | 20 分钟 | 1 | 在 L2 检查第 99 tick 仍在咏唱、第 100 tick 完成；覆盖提前中断、重复请求、结算前余额不足及重复 tick 不再扣费。运行 Wrapper test。 |

| 4. 接入服务端咏唱与结算 | 30 分钟 | 2、3 | 从连接获取发送者，按玩家驱动服务端 tick。成功时将已有 Mana.spend 的结果写入 1a 附件；向本人及旁观者同步开始与终态，中途进入观察范围时补发剩余进度。 |

| 6. 接入 R 键与手部水花 | 30 分钟 | 3、4 | 在物理客户端注册可重绑的 R 键，按下和松开各发送一次请求。按服务端状态更新本人及旁观粒子，在终态停止生成，已有粒子自然消亡。 |

## 联机验收记录

两名真实客户端在同一专用服运行。验收探针操作客户端 R 键映射，读取各自粒子引擎；魔力和移动速度通过服务端命令读取。

| 条目 | 实测结果 |
|---|---|
| 1 · 咏唱与旁观 | A、B 相距 4 格。咏唱中采样到 12、15 个水花，B 的截图可见 A 手部水花。速度 0.10000000149011612 → 0.05000000074505806。 |
| 2 · 完成只扣一次 | get 从 37 到 36。按住再等超过 5 秒仍为 36。 |
| 3 · 松键中断 | 从 37 开始，双方有水花；松键后走速恢复，再等 5.5 秒仍为 37，双方水花为 0。 |
| 4 · 完成后恢复 | 完成后走速恢复到 0.10000000149011612，水花归零。松开再按可再次开始。 |
| 5 · 魔力不足 | A 收到“魔力不足”，get 为 0，走速维持原值，两端水花均为 0。 |
| 6 · 冻结步进 | 冻结后开始，步进 99 tick 读数为 37、半速。再步进 1 tick 读数为 36、原速。 |
| 7 · 跨维度中断 | 首测发现持键跨维度会再起一次咏唱。改为仅消费新的按下沿后复测：进入下界走速恢复，两端水花归零，超过原定完成时间后仍为 37。 |
| 断线重连 | 咏唱中断开 A，同一客户端重连，速度恢复、两端水花为 0，再等一个咏唱周期仍为 37。重新按键可以咏唱并正常中断。 |
