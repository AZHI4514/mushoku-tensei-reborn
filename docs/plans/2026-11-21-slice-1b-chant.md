# 切片 1b · 徒手咏唱实施计划

2026-11-21 · 待审。按[切片规格](../specs/2026-11-21-slice-1b-chant.md)验收。

## Global Constraints

- Java 21（Temurin）、Minecraft 1.21.1、NeoForge 21.1.267、ModDevGradle 2.0.148、Gradle Wrapper 9.2.1。
- 水弹咏唱持续 100 个服务端游戏 tick。完成时经 Mana.spend 扣 1 点，中断零消耗。移动速度为相同条件下原走速的 50%，本片写死，切片 2 试玩后调整。
- 状态机与结算判断属于纯 Java core。玩家身份、游戏 tick、属性修饰和魔力附件由服务端适配层管理。客户端仅提交请求并显示服务端状态。
- 使用原版 minecraft:splash。终态立即停止生成新粒子，已有粒子约 1 秒后自然消亡。弹体、伤害、命中、自定义粒子及 3D 动画留在本片范围外。

## 任务与依赖

| 任务 | 预计用时 | 前置 | 实施与完成条件 |
|---|---|---|---|
| 1. 实现 core 状态机 | 25 分钟 | 无 | 定义待机、咏唱和终态转移。忽略重复开始，结束后只允许一次结算；魔力不足时拒绝开始，结算前再次确认余额。 |
| 2. 验证 tick 与扣费边界 | 20 分钟 | 1 | 在 L2 检查第 99 tick 仍在咏唱、第 100 tick 完成；覆盖提前中断、重复请求、结算前余额不足及重复 tick 不再扣费。运行 Wrapper test。 |
| 3. 注册三个定向网络包 | 20 分钟 | 1 | 登记 start_chant、interrupt_chant 两个 C2S 请求及 chant_state S2C。明确编解码字段；S2C 携带实体标识、状态、总时长和剩余 tick。 |
| 4. 接入服务端咏唱与结算 | 30 分钟 | 2、3 | 从连接获取发送者，按玩家驱动服务端 tick。成功时将已有 Mana.spend 的结果写入 1a 附件；向本人及旁观者同步开始与终态，中途进入观察范围时补发剩余进度。 |
| 5. 接入走速和生命周期 | 25 分钟 | 4 | 使用本次咏唱专属的临时速度修饰，避免重复叠加。松键、死亡、离线、维度切换时结束咏唱，清理修饰和待处理结算。维度切换按中断处理，并结束旧维度的旁观表现。 |
| 6. 接入 R 键与手部水花 | 30 分钟 | 3、4 | 在物理客户端注册可重绑的 R 键，按下和松开各发送一次请求。按服务端状态更新本人及旁观粒子，在终态停止生成，已有粒子自然消亡。 |
| 7. 联机核对完成与中断 | 25 分钟 | 5、6 | 两名玩家验收规格第 1–5 条。用 get 核对完成 37→36、松键仍为 37、魔力为 0 时拒绝。对比走速属性原值、半值、恢复值；从双方视角观察手部粒子停发及自然消亡。 |
| 8. 验证服务端计时与跨维度 | 20 分钟 | 7 | 验收第 6、7 条。冻结并步进服务端 tick 核对结算边界；让 A 在计满前跨维度，检查旧维度旁观者、A 的走速和原定完成时间后的 get 读数。 |
| 9. 交付检查 | 15 分钟 | 8 | 执行 Wrapper test、build、独立 runGameTestServer 及 python tests/contracts.py；在专用服核对客户端隔离。记录实测结果，通过后更新 AGENTS.md 的已实现边界。 |
