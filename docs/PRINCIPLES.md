# PRINCIPLES — 裁决原则

> 宪法层。每条必须能否掉至少一类想法；否不掉任何东西的是装饰。
> 本文件 + VISION = 宪法。

## 优先级声明（最高条款）

冲突时的裁决顺序：

> **宪法（VISION + PRINCIPLES）> 模块文档 > 当前切片 spec > 临时指令。**

两个会话遇到同一冲突必须得出同一结论；没有这条，分歧靠随机。

## 原则

1. **理解优先于数量。** 新法术只有在引入新的使用方式或组合时才加。
   第十个「火属性中级攻击术」不产生新理解 → 砍。

2. **成长可感知、不可购买。** 熟练度来自使用与试错，不能靠道具/等级
   直接跳过。用经验值一键升级的设计 → 砍。

3. **代价先于威力。** 每个法术在数值表里先填魔力消耗、咏唱时长、
   施法硬直，再填效果强度。代价填不出的法术 → 回炉。

4. **越级要有反噬。** 往低级术灌魔力必须付代价（魔力见底、施法硬直、
   短暂无力）。没有代价的越级 = 数值崩塌 → 砍。

5. **混合优于新增。** 优先让已有法术互相组合产生新效果（水+土=泥沼），
   而不是新增孤立法术。

6. **设定是骨架不是泥土。** 七级体系、四属性、咏唱三阶段必须照抄；
   原作没有的数值、习得方式、平衡参数由我们设计并写进模块文档。
   **不要为了「忠于原作」拒绝做游戏化决策，也不要为了好玩破坏骨架。**

7. **能 JSON 不代码。** 法术定义走数据文件，新增法术不该要改 Java。

8. **切片先于广度。** 一个能跑的闭环 > 十个半成品系统。

9. **注册即承诺。** id 进构建产物后不改名。

## 修改原则 = 修宪

要写明被否掉的想法类别发生了什么变化，并检查所有模块文档是否与旧原则
绑定了实现。
