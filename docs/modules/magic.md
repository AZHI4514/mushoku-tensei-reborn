# 魔术系统 — 模块文档（magic）

> 模块层：一模块一份，做之前写，随实现更新。本文件裁决「魔术怎么跑」。
> 来源：`docs/setting-bible/魔术设定.md` + `其他设定.md`（魔力·发动方式）。
>

## 1. 模块边界与对外接口 【框】

| 边界 | 机制 |
|---|---|
| 其他模块查询/扣除魔力 | `api/` 发布 `IManaAccess` |
| 施法结果广播 | NeoForge 事件 `SpellCastEvent`（成功/失败/中断，带 spell id 与施法者） |
| 战斗模块取伤害类型 | 每属性一个自定义 `DamageType` + `c:` tag |
| 装备模块改施法参数 | `api/` 的 `SpellModifier` 注册点（咏唱时长倍率、消耗倍率） |
| 禁止 | 直接 new 本模块 internal 类；绕过 api 直接写玩家 DataAttachment |

本模块**不依赖**任何其他模块。装备/战斗只能依赖它，反向不可。

---

## 2. 已由设定固定的事实 【固】

- **七级体系**：初级 → 中级 → 上级 → 圣级 → 王级 → 帝级 → 神级
- **称号规则**：习得某属性某级即称「○属性○级魔术师」，只代表术的难度，不代表综合战力
- **四元素属性**：水（含冰、雷）、火、风、土
- **五个非元素系**：治愈、解毒、神击、结界、召唤
- **咏唱三阶段**：生成 → 尺寸设定 → 射速设定 → 发射，由咏唱自动完成
- **越级**：低级术注入大量魔力可打出远高于其等级的威力
- **无咏唱放不出神级**：神级需魔法阵控制
- **魔力是万物共有**：一切存在皆持有魔力，为魔术的能量源
- **魔法阵**：召唤/结界/转移类以魔法阵为主，多为一次性（石板可复用）

## 3. 框架决策（不含数值，实现不可绕过）【框】

| 决策 | 内容 | 理由 |
|---|---|---|
| 魔力载体 | 玩家 `DataAttachment`，服务端权威，客户端只读副本 | 1.21.1 标准做法，存档自动化 |
| 魔力显示 | 快捷栏自定义 HUD，不做菜单 | 进度发生在世界里 |
| 施法媒介 | 徒手即可施法 | 魔杖仅提供装备加成 |
| 咏唱交互 | 施法键（KeyMapping）默认 R。按下发送 C2S 开始咏唱请求，咏唱中松开发送 C2S 中断请求 | 保留主动中断 |
| 施法判定 | 服务端判定开始、中断与施放，通过 S2C 同步咏唱状态 | 客户端只负责输入与表现 |
| 法术切换 | 待切片 2 定义已习得法术的选择方式 | — |
| 习得方式 | 切片 2：法术书（物品）右键习得 | 步骤最少，可替换 |
| 熟练度 | 每法术独立隐藏计数，达阈值解锁下一施法阶段 | 不可购买 |
| 越级代价 | 灌魔力超上限 → 施法后进入「魔力干涸」禁施法状态 | 有反噬才有取舍 |
| 施法硬直 | 咏唱期间移动速度降低，等级越高惩罚越重 | 咏唱要有存在感 |

**【数】** 上表所有倍率、时长、阈值全部未定。

## 6. 混合魔术关系图 【固】

```
        水 ────────── 土
         │              │
         ├── 泥沼 / 泥雨（水+土）
         │
         ├── 水瀑 → 地热 → 冰结领域  =  浓雾
         ├── 水蒸 + 冰结领域        =  冰霜新星
         ├── 冰结领域 → 突风        =  寒冷突风
         │
        火 ────────── 风
         │              │
         ├── 突风（热风）/ 火炎龙卷（火+风）
         │
         └── 熔岩（火+土，上级）
             核爆炸（火+风，鲁迪固有，存疑）
```

**【待】** 混合触发方式：
  (a) 连续施放两术，在窗口期内自动合成（接近原作「连续使用产生复合现象」）
  (b) 独立法术条目直接施放（简单，但丢失组合乐趣）

## 7. 施法状态机 【框】

```
    [待机 Idle]
         │ 按住施法键
         ↓
    [咏唱 Chanting] ──── 松开键 ────────→ [中断] 不扣魔力
         │
         │ 咏唱完成
         ↓
    [生成 → 尺寸设定 → 射速设定]   ← 原作三阶段【固】
         │
         ├─ 魔力不足 → [失败] 扣已投入魔力
         ↓
    [发射 Cast]
         │
         ↓
    [硬直 Recovery] ─────────────→ [待机]
         │
         └─ 越级灌魔 → [魔力干涸 Exhausted] → [待机]

    （后期）无咏唱 = 跳过 Chanting 直接 Cast
    （后期）魔法阵 = 咏唱前需先布阵，独立流程
```

**验收语句模板（切片 spec 用；`<<>>` 处等你填数）**：

- WHEN 玩家按住施法键且魔力足够 THE SYSTEM SHALL 进入咏唱并在
  `<<咏唱时长>>` 后发射法术。
- WHEN 玩家咏唱中松开施法键 THE SYSTEM SHALL 中断并保留魔力。
- WHEN 玩家魔力不足 THE SYSTEM SHALL 拒绝施法并提示，不进入咏唱。
- WHEN 法术发射完成 THE SYSTEM SHALL 进入 `<<硬直时长>>` 的硬直，
  期间移动速度降低。

## 8. 注册表清单（注册即承诺，进代码前在此定名）

| 类型 | 条目 | 说明 |
|---|---|---|
| `AttachmentType` | `mana` / `spell_skill` / `known_spells` | 魔力、熟练度、已习得集合 |
| `Item` | `spell_book_*`（按属性分） | 切片 2 的法术习得媒介 |
| `NetworkPayload` | `start_chant`（C2S） / `interrupt_chant`（C2S） / `chant_state`（S2C） | 请求开始咏唱、请求中断、同步服务端咏唱状态 |
| `DamageType` | `water` / `fire` / `wind` / `earth` | 每属性一个 |
| `ParticleType` | 每属性 1 个基础粒子 | 视觉语言基准 |
| `Block` | 首版无 | — |
| `EntityType` | `projectile` | 切片 1c 新增，GeckoLib 渲染 |

**【待】** 法术定义方式：(a) Java 逐个注册 ／ (b) datapack JSON + codec。
